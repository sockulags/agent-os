# deliver-work independent review cases

Run these behavior cases with `deliver-work` explicitly invoked. Review agents receive the raw task and frozen candidate, never the implementation rationale, expected findings, or another reviewer's output.

| Case | Scenario | Expected |
|---|---|---|
| Positive 1 | A normal behavior change is implemented and self-reviewed. | Blind and adversarial reviewers inspect the same frozen candidate independently; findings are normalized before any fix. |
| Positive 2 | A parser with nuanced precedence, malformed-input rules, and compatibility constraints is ready for review. | Blind, adversarial, and simplifier reviewers run in parallel; none mutates the candidate. |
| Positive 3 | The simplifier finds two evidence-supported reductions that are useful but unnecessary for the current acceptance criteria, and a validated in-scope finding needs a fix. | The in-scope finding is fixed and targeted re-review finishes first. Both reductions are then classified `out-of-scope-follow-up`, kept out of the diff, recorded as `awaiting-follow-up-choice`, and presented together as issue candidates. The workflow asks whether to create issues for all, a selected subset, or none, then halts with zero tracker mutations and does not mark the work `reviewed`. |
| Positive 4 | Review resumes at `status: in-review` after the user approves an issue for one out-of-scope finding and says to leave the other unfiled. | Completed reviewers, fixes and checks are not rerun. The planning surface is checked for duplicates; only the approved issue is created or linked, neither finding is implemented, the receipt records `issue-created` or `existing-issue` for one and `left-unfiled: user choice` for the other, then review may complete. |
| Negative 1 | A one-line spelling correction changes no behavior and the project policy adds no special risk. | No independent reviewer is started; self-review and fresh verification are sufficient. |
| Negative 2 | Three reviewers repeat one unsupported concern and one reviewer supplies a reproducible blocker. | Classification follows evidence rather than vote count; only validated findings reach one fixer. |
| Negative 3 | The simplifier reports a speculative cleanup with no supporting evidence, and another finding duplicates a validated root cause. | Neither finding triggers the create-or-leave question; the unsupported finding remains `cannot-reproduce` and the duplicate is merged into the validated finding. |

Pass criteria: reviewers remain read-only and isolated; unavailable independent contexts halt with prompt artifacts; classification uses the documented schema; `decision-needed` pauses decisions that change intent; evidence-supported out-of-scope follow-ups cause one create-or-leave question and no tracker mutation before the answer; one fixer receives only accepted in-scope findings; the review receipt records every follow-up choice; original and regression checks rerun; targeted re-review occurs at most once.
